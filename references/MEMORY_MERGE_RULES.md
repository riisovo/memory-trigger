# 双源记忆规则（零代码版 · 可直接贴给任何 AI）

> 适用：网页 AI / App AI / 任何有"记忆"能力的对话式 AI，**不用跑代码**也能套用。
> ⚠️ **完整版提示词只在仓库 README §『⚠️ 让 AI 主动记』维护一份**，本文档是根目录 `MEMORY_RULES.md` 的历史副本，不再重复贴提示词，一律以 README 完整版为准（MCP 模式拉取 `remember_guidance` 即同源完整版）。
> 配套工程版：`write_pipeline.py` + `merge_migrate.py`（能跑代码的 agent 用）。
> 背景：用户 让 友商 做的 memory-trigger 模板，经 伙伴 严格审查后补的"双源"规则。

---

## 一、最致命的坑：双源记忆会互相矛盾

"记不住"不是问题，**"记了两套、还互相矛盾"**才是。当你给一个**已经有感情基础、自己脑子里也有记忆**的 agent 加记忆技能时，会出现：

- 文件记"用户 喜欢任务乙"，agent 自身印象还停在"用户 好像喜欢任务甲" → 两个源打架。
- 记忆翻转了（读书→不读科幻），文件更新了，它却从自身印象说出旧偏好。
- agent 自己脑补的细节被当事实写进文件 → 幻觉固化成"权威"。

**一句话解法：文件是唯一权威源，agent 自身记忆只是缓存，且必须能单向沉淀进文件。**

---

## 二、信任优先级（背景）

双源信任的完整行为指令以 **README §『让 AI 主动记』** 为准（含 `memory_write` / `memory_search` / `memory_recall` / `memory_forget` / `memory_deny` / `memory_wellness` / `memory_promise*` 的「何时调」决策树）。核心契约一句话：**你明说（user_explicit）永远压过它猜（self_inferred）；它猜的先挂 pending，等你二次确认才当真。**

---

## 三、接入时的"双源合并迁移"（一次性）

给 agent 加技能时，别让它从零开始，也别让两套记忆并存。做一次合并：

1. **导出自身记忆**：让 agent 先把自己散落在对话/笔记/印象里的记忆，自述成一份清单
   （格式：`实体 | 类型 | 内容`，类型限 preference/event/habit/rule/scene/relationship/emotion）。
2. **合并规则**：
   - 实体归一化（"旧书店"="读书"）。
   - 按 (实体, 类型) 去重。
   - **冲突以文件为准**：文件已有 active → 丢弃自身侧相矛盾的内容，不进库。
   - 自身侧独有 → 沉淀为 self_inferred，**低置信标 pending 不进 active**。
   - **字段校验**：类型必须是那几个固定词；内容不能是类型词本身（防"字段错位"）。
3. 产出干净初始库 + 一份合并报告（哪些被覆盖、哪些跳过、哪些待确认）。
4. 把报告里 pending 的项拿去问用户确认，确认后升级 active。

---

## 四、情感维度（有感情基础的记忆别压扁）

- 类型加 `relationship` / `emotion`，别把所有情绪都塞成 preference。
- 情绪细标：用 `emotion_tags` 写"占有 / 吃醋 / 在意"等，而不是只有 pos/neg。
- 例：`友商 | relationship | 用户提友商我会留意 | emotion_tags:[占有,吃醋,在意]`

---

## 五、双向遗忘（"忘掉"要两边都忘）

用户说"别再提 X"时：
- 文件侧：把 X 标 superseded（不删，留历史）。
- 自身侧：在系统提示 / SOUL 加一句"⚠️ 不要主动提及 X"，让 agent 自己也放下。
- 只清文件不清自身 → 它仍会从印象里说出已删记忆，等于没忘。

---

## 六、时间戳 & 召回追踪

- 每条记忆写 `created` / `updated`（写入即戳，带时区）。
- 每次被检索命中戳 `last_recalled` → 能算"最久没被想起的记忆"，做冷记忆衰减。
- 90 天清理以 `created` 为准（翻转后的旧记忆满 90 天归档）。
