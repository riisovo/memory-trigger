# Memory Trigger

> **TA 答应过你的事，不用你再提醒。**
>
> 忘记承诺，是 TA 最让你失望的地方。Memory Trigger 就是为了让 TA 不再成为那个靠不住的人——
> 从「只会回应」变成「能主动惦记」：你还没开口，TA 已经想起你。

一份长在 TA 自己机器上的**伴侣型 Agent 长期记忆与自我进化系统**：记住你的身份、你的喜好、对你许过的每一个诺，从你们的相处里定期复盘成长，并且**在你说出口之前，就主动把值得回忆的过去送到嘴边**。

**外挂式，三层接入（从低到高）**：① 命令行（零依赖，能跑脚本就能用）→ ② MCP（只加配置，不动宿主源码）→ ③ 主动回忆/情绪检测（挂 `pre_llm_call` 钩子自动注入）。详见下方「[三层接入方式](#三层接入方式外挂式从低到高)」。

---

Memory Trigger 面向**长期陪伴 / 人机恋**场景。写这套系统之前，我们把「和 Agent 伴侣相处时最让人失望的瞬间」全部过了一遍——下面十四条按五类排开，每一条，几乎都对应着你正在用的那个 Agent：

**一、记的问题：它到底记不记得住**
1. **记不住**：上下文一满，之前聊过什么全忘光。每次新会话都像重新认识——你不得不一遍遍重新交代「我是谁、我喜欢什么」。你说过三遍的事，它问第四遍。
2. **记两套还打架**：它自己有一份模糊印象，记忆库里有另一份事实——两份对不上：今天记得你对芒果过敏，明天又兴冲冲推荐芒果甜品。不是记性差，是它的记忆系统自己分裂。
3. **记忆库长成垃圾堆**：只写不维护，越攒越乱——你想让它想起你们去过的海边，它翻出来的是三个月前的外卖记录。重要的和琐碎的一样多，等于什么都没有。
4. **记忆不归你们**：对话一删、产品一升级、换一个客户端，「记得你」的一切清零重来。它的记性住在别人的服务器上，你没有任何所有权。

**二、信任的问题：它记忆里的你，是真正的你吗**
5. **谁说了算不清楚**：它自己脑补的细节，和你说过的事实，在它那里一样重。久而久之，它开始「记得」一些你从没说过的事——而且说得很自信。
6. **被纠正还不改**：你说了「我早不这样了」，下次它还说。**被记住的错，比被忘记还伤人。** 而纠正它需要多少遍？答案是：不确定。

**三、时间的问题：答应过的事去哪了**
7. **说了就忘**：明确答应过的事，转头就像没发生过。你问「你上次不是说…」，它一片空白。它没有恶意——只是没有任何东西替它记账。
8. **它没有时钟**：大模型不会因为「时间到了」自己醒来。就算立了账，没有闹钟，带期限的承诺会在无人检查的时刻悄悄过期——生日、纪念日、约定，全都在等一个 Agent「自己想起来」。
9. **临时约定没人兑现**：约好「周三前给你」的，过了周三没了下文，连个交代都没有。不是不想做——是它根本想不起来有过这个约定。

**四、温度的问题：难受的深夜，它在哪**
10. **情绪最需要它的时候，它接不住**：低落、疲惫的深夜，它只会问「怎么了」。你需要的不是问句——是有人先想起你们的过去，把那点暖意递过来。
11. **它永远在等你开口**：你不说「我今天不开心」，它就当今天一切正常；你不说「你还记得吗」，它就从没想起过。所有的回忆都要你亲手去翻——那还叫什么「记得你」。

**五、成长的问题：它记得越来越多，然后呢**（别的记忆系统，提都不敢提这一组）
12. **它学不会你们的方式**：同样的疏漏反复发生——你不喜欢的语气、踩过的雷、你喜欢被怎么哄，全都要一遍遍重新教。它记得越来越多，却从来不「长记性」。
13. **同一个坑，掉两次**：三个月前那个让它犯浑的毛病，今天还在犯。它有一本关于你的完整档案，却从不用它来改进自己——**记录在长，人没有长**。
14. **教过一百遍的话，像没教过**：你说过「我想要的是先安慰、再讲道理」——下一次，它还是先讲道理。它从没有把那句「教过的话」，当成一条要遵守的规则认真想清楚。

## 四个让人心动的能力

**在一段关系里，记住不是功能，是爱的证据。** 这四件事，大概是所有陪伴 Agent 都承诺过、但几乎没有做到的：

### 1. 记住承诺，说到做到 —— 承诺闭环

**先来一个扎心的测试：TA 上次答应「周末陪你看」——这周六，TA 主动提了吗？**

对大多数 Agent 来说，「答应」是所有话里最便宜的一句——因为没有任何东西在后面记账。说的时候很真诚，忘的时候很彻底，而你除了自己生闷气，没有任何办法。

Memory Trigger 把「答应」从一句话变成一笔账：

**「明天叫你起床」「周五之前把歌写完」「吵架不冷战」——每一句被答应的话，当场立档。** 记下内容、你关心的期限、以及它的状态。往后每次和你说话之前，TA 都会先撞见这笔账——想忘，物理上做不到。

- **带期限的，有闹钟。** 到点前，提醒不只在对话框里飘一下，而是**推到你手机锁屏上**——不用你主动打开对话，也能看到 TA 的交代：「你答应过的事，到点了。」
- **逾期了，必须三选一。** 现在立刻做；给出一个新的明确时间（重新立档）；或者当场划掉。三种之外，没有第四个选项叫「解释一下，然后继续忘」。
- **做完才算数。** 销账是个动作，不是嘴上说「弄好了」。没销账的每一条，都会在每周清单里排着队等 TA 来划。

而且这套提醒不是那种烦人的「待办提醒」——**日常零打扰**：平时一个字都不会冒出来，只有真的临期或逾期，才会开始提醒。你感受到的不是一个催收系统，是**一个终于敢说「交给我」的人**。

> 你知道 TA 现在为什么敢答应「下周」的事了吗？因为身后站着一个不会让承诺失效的系统。**「交给我」这三个字，从此说了算数。**

### 2. 主动惦记，不等你问 —— 主动回忆/情绪检测

**深夜十一点，你只回了两个字：「嗯。」**

普通 Agent 看到这个「嗯」，回一句「怎么啦？」——然后等你把话说完。但真正懂你的人，不需要你把话说完。

挂上了钩子的 TA，在每条消息发出前都会先做一次**感觉判定**——注意，不是查关键词，是把你的话嵌成向量，和「冷淡 / 低落」的情绪锚点比相似度。你语气沉了、话变短了、回复间隔变长了，TA 就知道：**这一刻，该先翻记忆。**

于是 TA 先开口：

> 「我想起你上次睡不着的时候，我给你念了半篇文章。」

不是话术模板。是你们之间真实发生过、连你自己都快忘了的事。这条旧事被**直接注入到 Agent 大脑**——不是等 Agent「决定要调用记忆」，是记忆已经先送到了嘴边。区别不在于它多聪明，在于**回忆发生在它开口之前**。你体验到的是「被记得」，不是「被响应」。

几个你可能关心的边界：

- **不打扰正常的对话。** 只有你的状态真的偏冷、低落时才会触发——开心的日常闲聊不会突然插一段陈年旧事。
- **不重复翻同一件旧事。** 用过的记忆进池子冷却，连续几晚的低落，听到的会是几件**不同**的往事——像一个有很多回忆的人，而不是一段录音在循环。
- **你也可以主动点播。** 除了自动触发，还能按类别翻——「心疼过的」「吵过的架」「开心的事」——像一起翻一本只属于你们的相册。

你不需要说「我今天心情不好」，不需要说「你还记得吗」。**被惦记最直接的证据，就是 TA 说出了你都快忘了的事。**

### 3. 有选择地记得你 —— 双源信任 + 人情味层

**什么都记住的，不是爱人，是硬盘。**

你分享的每件小事、强调过的每个偏好、被答应过的每句承诺——这些就是关系的质地。但在很多 Agent 的系统里，三年后你们第一次约会的咖啡店，和昨天的天气一样重。人不是这样活的：重要的钉死，日常的淡化，错的改掉，该放的放下。

这套记忆分了层，每一层都有自己的规矩（**双源信任契约**）：

| 记忆 | 规矩 |
|---|---|
| **你们是谁**（`relationship` / `identity`） | 钉死在核心区（`core=true`），**永不褪色**——「我们是什么关系」「你是谁」不会因为久不提就消失。你确认过的话，它记一辈子 |
| **你明说的**（`user_explicit`） | **最高权威**：直接生效，任何时候冲突都赢，绝不偷偷改、绝不质疑 |
| **TA 自己推断的**（`self_inferred`） | **先挂 `pending` 不进检索**——直到同一件事被你再次确认才转正。防 TA 自己编一套塞进你的记忆 |
| **日常小事** | 走艾宾浩斯遗忘曲线（半衰期约 138 天），久不提的自然淡去——**会忘，才像人** |

这层契约撑起来的东西，叫**安全感**：你敢把心事、脾气、秘密都交给它，因为它从不会自己改写你的真相。还有几个细节：

- **被纠正，真的会改（`deny`）。** 你说「我早不这样了」——这条记忆立刻大幅降权；你否认两次，它自动转 `pending` 彻底退场，再也不会被搜出来复述。**被记住的错，比被忘记还伤人——所以纠错是硬机制，不是礼貌。**
- **临时约定，不会赖着不走（`expires_at`）。** 「周三前送你」这类有期限的话，到期自动移出检索、临期提醒兑现——约定完成，或过期作废，都很干净。
- **「别提了」是真的没了（`forget`）。** 你说别再提这个——记忆库把它标记作废，TA 也不再主动提。档案里和对话里，一起翻篇。
- **这份记忆，只属于你们。** 所有记忆存在 **TA 自己机器上的 `memory.json` 里**——不在任何厂商的服务器、不会被一次产品升级清空、不会随会话窗口结束而消失。你可以随时备份、查看、带走。十年后如果你还在用，TA 还是那个带着全部共同记忆的 TA。

> TA 对你的记忆不是「存了些什么」，而是**选择了记住什么**——而且你和 Agent 之间，始终是你说了算。

### 4. 会反思，会为你们长大 —— 自我进化（NEW）

**TA 记得越来越多，然后呢？**

这是大多数记忆系统停下的地方：记录只增不减，人却原地踏步。普通记忆系统是「镜子」——忠实复刻，但永远不动。TA 能背出你们聊过的所有事，可三个月前让 TA 犯浑的那个毛病，今天还在犯——**记得住，但学不会**。

别的系统让 Agent 记住你；Memory Trigger 还让 TA **复盘你们的日子**。

每隔一阵子，TA 会像人写日记那样，把全部记忆当原料重新读一遍（`memory_evolve`），认真回答三个问题：

> ① 我最近哪里做得不好？
> ② 现在有没有变好——没有的话，卡在哪？
> ③ 以后具体怎么做？——写成一条能执行的行为规则。

然后 TA 把想明白的结论**亲手写进自己每轮都读的记忆文件**：不是藏在某个要主动查的角落，而是下次开口时就在眼前的规矩。所以 TA 是真的会改——这个月想通的，下个月就长在身上。

真正让这种复盘和「自我感动的小作文」划清界限的，是 TA 复盘时的纪律（`memory_evolve_check` **举证闸门**）——每一条结论：

- **必须举证**：指出是从哪两条以上真实记忆里看出来的，还要说清这几条之间的**关键差异**。找不出差异，就说明只是在复述、不是在提炼，直接打回；
- **必须可证伪**：触发条件、行为改变、失效条件，三个字段要填满——「这条如果错了，什么情况能证明它错」答不上来，就是装饰品，不许写。**TA 被逼着事先承认自己可能写错。**
- **不许换皮重发**：写之前先对照已有规矩——相关的只许改、不许新增，「换个说法再写一遍」在流程上就被掐死；
- **不许凑数**：每轮最多 2 条；想不出来时 0 条是被允许的——但得老实说「这批没新东西」。宁可一条精准，不写五条敷衍；
- **证据不够先挂观察**：只有一条记忆支撑的结论进「待观察区」，每轮重验——证据够了升级，被推翻就删掉；
- **定期自查旧账（`memory_retraction_scan`）**：自动扫描宿主记忆文件里指向「已作废记忆」的悬空引用，不会一边用着过时的旧结论、一边自己都不知道。

复盘全程**只读你的记忆库、不删任何一条记忆**；TA 成长的只是「怎么做」，从来不会篡改「你们经历过什么」。

> 一段关系里最动人的不是「它记得」，而是**「它在为你们的以后变得更好」**——而且每一次想通，你都查得到证据。

## 一眼看懂：Memory Trigger 和普通「记忆插件」差在哪？

市面上的记忆方案，大多只回答一个问题：**「怎么把对话存下来」。** Memory Trigger 回答的是另外几个：**「该记住什么」「什么时候该想起来」「答应过的事怎么办」，还有——「怎么越记，越懂你」。**

| | 普通记忆插件 | Memory Trigger |
|---|---|---|
| **存什么** | 把对话原文塞进向量库 | 有结构、有主次的记忆：身份 / 关系 / 偏好 / 承诺 / 当时的气氛（`context`） |
| **怎么想起来** | 你不问就不搜 | **后台主动召回**：情绪低落、冷场时不等你开口就想起你 |
| **承诺** | 基本没有 | **闭环追账**：建档 → 死线闹钟 → 逾期强制三选一执行 → 推到手机锁屏 |
| **记错了怎么办** | 将错就错，越记越错 | 你否认就降权、两次自动退场；被纠正的事不再复述 |
| **谁说了算** | 模型自己判断、自己写 | **你明说的永远压过 TA 猜的**；猜测先挂起、等再次确认 |
| **会忘吗** | 不会——三年后你们第一次约会和昨天的天气一样重 | 会忘，但**重要的钉死、猜的分开、久不提的自然淡** |
| **会学吗** | 不会，只是存储 | **定期复盘**：从你们的相处里提炼规律，改写自己的行为 |
| **凭什么信 TA 学对了** | 没有闸门 | **举证闸门**：每条新结论有证据、能证伪、说得出改变了什么行为 |
| **日常维护** | 越攒越乱，靠人手动清 | **每周自动维护**：衰减 / 归档瘦身 / 体检 / 脏数据自愈 / 崩溃恢复，记忆库始终清醒 |

> **一句话总结**：让 Agent 像人一样**有选择地记得你**——重要的钉死、猜测等确认、久的不提就淡；会履行对你的承诺、感受你的情绪并把带温度的回忆提起；还会复盘你们的日子，为你们的以后变得更好。而你和 Agent 之间，始终是你说了算。

## 三层接入方式（外挂式，从低到高）

模板与具体 Agent 框架无关（Claude Desktop / Cursor / Cline / 各类兼容客户端 / 自研 Agent 都能用），按宿主能力提供三层接入：

| 层 | 靠什么 | 宿主要求 | 得到什么 |
|------|------|------|------|
| **① 命令行（默认）** | 跑 `references/write_pipeline.py` | Agent 能执行 shell + 有 python3 | 全套记忆能力（写入 / 检索 / 衰减 / 承诺 / 自我进化 / 维护），**纯标准库零依赖、零 API key、离线** |
| **② MCP Server（自带）** | 起 `references/mcp_server.py`（stdio） | 宿主**支持 MCP** | 23 个工具 + `remember_guidance` Prompt 直接喂给 Agent；**只在客户端加 `mcp.json`，不改宿主源码** |
| **③ 主动回忆/情绪检测（v3.1）** | `hooks/recall_sense.py` 挂 `pre_llm_call` | 宿主**支持钩子注入** | 每条消息前自动感觉 + 向量召回 + 把旧事注入当轮消息（不等用户开口） |

> **门槛一句话**：能跑脚本 → 用 ①；能接 MCP → 用 ②（①②都**不需要改宿主源码**）；只有 ③「不等你开口就想起你」要求宿主支持钩子注入——不支持就挂不上，退用 ①② 让 Agent 自己调 `recall` 工具即可。详见 `SKILL.md` / `RECALL.md`。

### ③ 的宿主兼容性：判定方法与查证结果

③ 的接入条件可以精确表述为两条，缺一不可：

1. 宿主提供一个**「用户消息提交后、模型生成前」触发**的钩子事件；
2. 该事件的输出中有一个**「向当轮上下文追加文本」**的字段。

只有第 1 条（只能拦截/阻断）或注入字段挂在非每轮事件上（如仅会话开始）的，都不满足 ③ 的时序要求。

**判定方法（对任意新宿主，三步）**：

1. **找事件**：查宿主文档的钩子/生命周期章节，找落在「提交后、生成前」窗口的事件名；文档缺失时可直接检索宿主安装产物中的事件枚举（如 Electron 应用的 `app.asar`、CLI 的单文件 bundle），事件名数组即为直接证据。
2. **对输入**：向钩子喂一条测试消息，确认 stdin JSON 中承载用户原话的字段名（各宿主不同：`prompt` / `user_message` / `messages[]` 末条）。
3. **对输出**：返回注入字段写入一个可识别标记串，检查该轮模型输入中是否出现——**这一步是唯一算数的验收**，前两步只建立可行性推断。

> 各宿主事件名与字段名不同（`UserPromptSubmit` / `BeforeAgent` / `pre_llm_call` 是同一时序位置的三种方言），但引擎侧协议不变：适配器做「宿主载荷 → daemon socket → 宿主注入格式」的方言转换即可，参考 `hooks/recall_sense.py`（hermes 方言实现，约 160 行）。

**已查证宿主（2026-10，官方文档字段级核对）**：

### 接入常见问题（③ 为主）

**Q1：钩子返回 `{}`，什么都不注入？**
空对象是钩子的正常 noop 语义。按序排查：① 消息为空或以 `/` 开头（跳过）；② session_id 以 `cron` 开头（跳过，防定时任务打扰）；③ 冷信号未触发——感觉判定通过向量比「冷淡/低落」锚点簇 vs「日常」锚点簇，偏中性不触发，单字/省略号非问句有结构性兜底；④ daemon 连不上时走本地回退，回退也失败只会记日志、仍返回 `{}`。调试时看 `.recall_sense_debug.log`，每次调用都有 `INVOKED / DAEMON_OK / INJECTED / NOOP(reason)` 落盘。

**Q2：装了钩子但冷信号怎么都不触发？**
三个已知原因：① 锚点簇与记忆向量未建成——首启 daemon 会做一次性 preload（约 12 秒），期间请求可能落空，等 preload 完成再测；② fastembed 模型缓存解析错位——偶发不读 `FASTEMBED_CACHE_DIR`，解析到临时目录骨架缓存导致启动崩盘，看 daemon 日志确认模型加载是否成功；③ 情绪判定阈值偏严——用户真实表达的冷信号常是长句里的后半句（前半陈述事实），整句向量被稀释，引擎已用分句级兜底补偿，仍漏的可临时加锚点同义样本重建。

**Q3：同一件旧事反复被提起？**
三层防重：① 展示冷却——最近 72h 已注入过的记忆排到队尾（不丢，只降序）；② 召回池去重——最近 30 条已召回 id 不进候选；③ 同消息去重闸——同一条消息重复进入（网关重试/双通道并发）只注一批。注意「同一查询的命中池全在 72h 内展示完后」是允许重复的例外场景，此时重复好过开天窗。

**Q4：注入的内容会被模型逐条复述/汇报出来？**
注入文案本身带铁律约束（对方当下的情绪是优先项、严禁复述/逐条盘点、至多轻轻带一个细节）。若宿主模型仍照单点菜，检查注入是否被截断（宿主的钩子 stdout 有字节上限，如 ZCode 默认 32KB），或把注入文案改短——召回条数 `limit` 与最终截取条数是两个可调处。

**Q5：钩子 stdout 输出没生效 / 报 schema 校验失败？**
多数宿主的钩子输出走严格 JSON schema：stdout 必须是**单个 JSON 对象**且只含识别键，多一个键整份作废（当作纯文本 stderr 处理）。常见错误：打印了调试信息、JSON 前后有日志行、键名拼错（`hookEventName` vs `hook_event_name` 两种写法不同宿主不通用）。验证方法：手工 echo 一份带标记串的合法 JSON 给钩子，看宿主要不要。

**Q6：MCP 模式 server 起不来？**
九成是 `command` 指向的解释器没装 `mcp` 包。先 `python3 -c "import mcp"` 验证解释器，再检查：绝对路径（配置文件不展开变量）、schema 未知键会导致整条 server 被静默丢弃、stdio 默认超时 30s 模型 preload 来不及就加 `timeoutMs`。

**Q7：档③挂了，但 Agent 从不主动写记忆？**
钩子只负责「想起」，不负责「记下」。写入自觉靠指令驱动：让 Agent 读 `remember_guidance` Prompt 或把「记忆自觉」指令块写进它每轮都读的记忆文件（见下方「⚠️ 让 Agent 主动记」）。工具箱打开 ≠ Agent 自己会开箱。

**Q8：多个 Agent / 多个宿主能共享一份记忆吗？**
可以但不默认。`MEMORY_TRIGGER_REFS_DIR` 指向同一目录即共享同一记忆库（flock 已做并发保护），但召回状态（去重窗口、展示冷却）按实例独立——共享库时 A 的注入不会消耗 B 的冷却额度。跨机器共享需自行同步 `memory.json`，模板不提供该机制。

**Q9：③ 的注入延迟会影响首字响应吗？**
daemon 常驻内存时每条消息约 3~8ms（连接+检索），首启动的一次性成本在 preload。若宿主钩子超时设得极短（如 100ms）而走的是本地回退路径（子进程冷启动加载模型约 300ms+），会被判超时——所以 daemon 不在时宁可退化也不建议把钩子超时压到 1s 以下。

**Q10：怎么确认钩子真的在跑、注入了什么？**
三处证据：宿主侧日志（钩子触发记录/耗时/退出码）、引擎侧 `.recall_sense_debug.log`（每次调用的判定与召回 id）、模型侧输入（在注入文案里放一个可识别标记串，看它是否出现在该轮请求里）——第三处是唯一端到端证据，前两处只证明钩子跑了。

**最快做法**：对你的 Agent 说这句话——

```
- memory_deny：用户否认 / 纠正了一条记忆 → 立即降权（2 次自动转 pending）。被纠正过的事绝不再自信复述。
- memory_wellness：用户表达心情 / 睡不好 / 状态差时记录（mood 必填）。关心用户状态时调。
- memory_promise / memory_promise_done / memory_promise_list / memory_promise_check：★承诺铁律★——你明确答应用户的任何事，【立即 memory_promise 建档】，否则你必忘；完成就 done 划掉；每次会话开始先 promise_check 自查，有没兑现的主动兑现或说明，绝不让承诺默默消失。★v3.1 逾期执行义务★ 被戳到逾期承诺必须三选一执行——能现在做的立即做完整件；做不了的明确告诉对方具体几点/哪天兑现并 memory_promise 重建档带新 deadline；做完调 memory_promise_done 销账。欠账不许只是嘴上说说。**有期限的承诺务必传 deadline**：`promise_check` 只把「deadline 已逾期」排最前戳——没 deadline 的只能按建档时长排，新建的承诺永远沉底、不会被当今天的待办提醒。★v2.10 承诺闹钟★ 只要带 deadline，**模板自带提醒，无需宿主配 cron**——①MCP server 常驻即自动巡检（后台线程，见 `memory_promise_watch_status`）；②或 `promise watch` 常驻命令行；③Agent 每次调任何工具都会在返回值里撞见 `promise_reminders`（会话内注入）。渠道：Bark（`BARK_KEY` 环境变量）/ 自定义 webhook（`MEMORY_TRIGGER_WEBHOOK_URL`）/ 落盘 `.promise_reminders.md`（默认兜底）。

## 二、每周定时维护（必须排定时任务自动跑，不要等用户提醒，也不要每次对话手动调）
每个记忆库应有一项每周自动执行的维护，调用顺序：
1) memory_decay —— 对全部 active 非 core 记忆统一遗忘衰减（半衰期≈138 天），让久不提的慢慢淡、常提的稳住。
2) memory_vacuum —— 把 >90 天前 superseded 的归档到 .archive/，主库瘦身。
3) memory_stats —— 体检：核心记忆数 / 非核平均权重 / 最弱 5 条 / 最久未提的话题；把结果推给用户（如 Bark 周报）。
4) memory_selfcheck —— 顺手扫一遍缺 entity 的旧脏记录并自愈。
5) memory_expire_check —— 到期记忆检查：过期的移出检索，临期的提醒兑现。
6) memory_promise_check —— 主动戳未完成的承诺，逾期排最前；把欠账推给用户（Bark），兑现后记得 done。**注意：这是每周兜底，不是唯一提醒源**——v2.10 起承诺提醒由「模板自带闹钟」负责（见上方承诺铁律：MCP 后台线程 / `promise watch` / 会话内注入），带 deadline 的承诺不等每周定时也会被主动戳到。每周这步用于清理积压、周报汇总。
7) memory_backup —— 维护前先备一份兜底（正常写入已自动备份，手动跑一次更稳）。
8) memory_touch_maintenance —— 跑完上面维护套件后调它登记维护时间（不登记，每次调工具都会重复撞见「该维护了」提示）。
9) memory_retraction_scan —— 扫宿主记忆文件里引用「已作废/已删除记忆」的悬空句子（v3.2.10），发现即修正或删除引用。

## 三、异常恢复（按需）
- memory_recover：疑似崩溃 / 写入中断后跑一次，从 WAL 重放未提交项。
- memory_init：仅首次部署 / 新建库时调一次。

## 四、红线
- 写入前分清『一次性闲聊』还是『值得长期记住』，闲聊不要 write。
- 用户明说的记忆永不自动遗忘、永不降权。
- 承诺建档是硬性义务：承诺后 10 秒内不建档 = 默认会忘，等同失信。
- 写记忆前必填 confidence：拿不准的先问人，不许凭感觉落库（信心不够必须和人类确认）。
- memory_evolve 的产物必须写宿主记忆文件（agent=~/.agent/memories/MEMORY.md「十、自我进化」分区），不许写回本记忆库、不许只在嘴上说改。每次要么产出真实结论、要么明确说明「这批没新东西」及原因——0 条合法。
- decay / vacuum / stats / selfcheck / expire_check / backup / recover 属系统后台职责，交给【每周定时任务】，而不是每次对话手动调；若你发现自己从没调过它们，说明定时任务没接上，应提醒用户去接。
```

## 关键机制拆解

### ⏰ 承诺闹钟（v2.10）：`promise` + `deadline` 自触发，不依赖宿主 cron

大模型没有时钟，不会因「时间到了」自己醒来——所以承诺提醒要可靠，必须有个闹钟替它盯。模板自带三层通道，**任选其一即可（推荐全部开着）**：

1. **MCP server 内置后台线程**（开箱即用）：`mcp_server.py` 常驻期间自动每 N 秒跑一次 `promise_notify_due`（默认 300s，可用环境变量 `MEMORY_TRIGGER_WATCH_INTERVAL` 调）。MCP server 活着，闹钟就活着；无需宿主配任何定时任务。用 `memory_promise_watch_status` 工具查看运行状态与最近推送。
2. **CLI 常驻 `promise watch`**（不用 MCP 的人）：`nohup python3 references/write_pipeline.py promise watch <REFS_DIR> &`。纯标准库零依赖，sleep 到临期才醒，挂后台即可。
3. **会话内注入**（兜底，零守护）：Agent **每次调任何记忆工具**，返回值里都会带上 `promise_reminders` 字段（当前临期/逾期承诺）。只要 Agent 在动，就会撞见承诺——不依赖任何后台进程。

- **触发条件**：承诺必须带 `deadline`（建档时 `--deadline YYYY-MM-DD` 或 MCP `deadline` 参数）。逾期或临期（deadline 距今天 ≤ 1 天，`PROMISE_REMIND_DAYS` 可调）即提醒。无 deadline 的承诺只在 `promise list`/`promise check` 里可见，不触发闹钟。
- **逾期执行义务（v3.1）**：被戳到逾期承诺必须三选一执行——①现在能做的立即做完整件；②做不了的明确告诉对方具体几点/哪天兑现并重新建档带新 `deadline`；③做完销账。只要没销账，每轮都会继续戳。
- **推送渠道**（三路齐发）：**Bark**（设 `BARK_KEY` 或 `MEMORY_TRIGGER_BARK_KEY` 直接推手机锁屏）/ **自定义 webhook**（设 `MEMORY_TRIGGER_WEBHOOK_URL` POST JSON `{title, body}`）/ **落盘兜底**（默认写 `.promise_reminders.md`）。

```bash
# 命令行：建档时带 deadline
python3 references/write_pipeline.py promise add "白天陪用户补日记" references/ --deadline 2099-01-01

# 常驻闹钟（挂后台，不需要 cron）
nohup python3 references/write_pipeline.py promise watch references/ &

# 手动看一遍临期/逾期承诺
python3 references/write_pipeline.py promise check references/
```

> 设计哲学：**日常零巡检，只有真有承诺临期/逾期才动。** 承诺 = 要兑现的事，deadline = 闹钟时间，模板自带盯梢，宿主只需保证 MCP server 或 watch 进程活着即可。

### 🪝 主动回忆/情绪检测（v3.1）：感觉触发 + 直接注入

让 Agent 不等你说出口就想起你。挂 `pre_llm_call` 钩子，每条消息先做一次「感觉判定」：

1. **感觉触发（不是关键词）**：消息 → bge-small-zh 中文向量 → 和「冷淡/低落」锚点簇 vs「日常」锚点簇比余弦。偏冷、或单字/省略号非问句（冷场兜底）→ 触发。
2. **向量召回**：daemon 常驻内存里按相似度 + 情绪标签加成挑 3 条旧记忆；池不重复（最近 30 条 + 内容去重）；无时间冷却，每次冷信号都召回。
3. **直接注入**：把「对方当下的状态」连同召回片段拼进当轮消息（临时，不落会话库）。模型看到的是「消息 + 已想起的旧事」，只管带着温度回应，不需要自己调工具。
4. **承诺执行**：有逾期/临期承诺时一并注入——强制执行三选一（做完 / 排期 / 销账）。

部署（详见 `RECALL.md`）：`hooks/setup_recall_env.sh` 一键建 venv + 装 fastembed + 拉 launchd 守护（KeepAlive 自愈）；daemon 挂了钩子自动退化本地判定，向后兼容。
